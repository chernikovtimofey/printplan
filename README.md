# AI Assistant для STE Slicer


> **Что есть:**
> - плагин STE Slicer `plugin/AIAssistant`: чат с языковой моделью в браузере, агент с вызовом инструментов, MCP-сервер и инструменты управления слайсером;
> - пайплайн анализа `plugin/AIAssistant/printplan`: из задания и 3D-модели он строит проверенный план печати.
>
> **Что не проверено:**
> - данные графа материалов (помечены `"reviewed": false`);
> - пороги и веса правил: подобраны вручную, их нужно перепроверить на размеченных деталях.

Пакет `plugin/AIAssistant/printplan` получает текст задания (фраза или .docx с техническим заданием) и 3D-модель, а возвращает план печати для Stereotech Hybrid 530 V5.2.4:

- режим 3D / 5D Spiral / 5D Spiral Full;
- профиль качества и материал;
- настройки слайсера, каждая с причиной;
- ориентацию и размещение;
- риски, подсказки по конструкции и объяснение решений;
- упорядоченный список действий для MCP-инструментов плагина.

Код совместим с Python 3.5 и использует только numpy (scipy — по желанию), как в дистрибутиве слайсера. Пакет не зависит от остального плагина и работает также из командной строки.

Подход основан на работе Du Z., Zheng Q., Zhang X. «Task-Driven 3D Printability Assistance via Geometry- and Knowledge-Grounded LLM Reasoning» (arXiv:2608.22128, 2026): всё, что можно вычислить, вычисляет код, а языковая модель выбирает только среди допустимых вариантов и объясняет решение.

## Плагин

Плагин добавляет в STE Slicer меню **AI Assistant** и открывает окно чата в браузере (локальный сервер на 127.0.0.1). Пользователь прикрепляет модель (STL, OBJ, 3MF), техническое задание (.docx) и фото, а ассистент:

1. выбирает режим печати, профиль, материал, настройки и ориентацию с помощью пайплайна `printplan`;
2. применяет их в слайсере, нарезает модель и объясняет решения;
3. вносит точечные правки по просьбе пользователя;
4. сохраняет G-code и проект 3MF — по просьбе или кнопками под результатом нарезки.

Каждое действие в слайсере видно в чате карточкой инструмента. Те же инструменты доступны внешним клиентам по протоколу MCP (`POST /mcp`, JSON-RPC 2.0). Без ключа языковой модели план строится по правилам.

| Модуль | Что делает |
|---|---|
| `AIAssistant.py`, `plugin.json` | расширение слайсера (API 5): меню, запуск сервера, настройки в настройках слайсера |
| `agent/server.py` | HTTP-сервер: окно чата, `/api/*` с журналом событий, MCP |
| `agent/agent.py` | диалог с LLM: вложения, цикл вызова инструментов, работа без LLM |
| `agent/tools.py`, `agent/mcp.py` | инструменты (общие для чата и MCP), `plan_print`, протокол MCP |
| `agent/slicer_live.py`, `agent/bridge.py` | работа с STE Slicer, только через главный поток Qt |
| `agent/slicer_fake.py` | слайсер в памяти для тестов и `tools/dev_server.py` |
| `web/` | окно чата без внешних библиотек |

Установка и использование описаны в `plugin/README.md`.

## Быстрый старт

```bash
conda env create -f environment.yml        # Python 3.5, numpy 1.15, scipy 1.1, pytest
conda activate ste-assistant

pytest -q                                  # живые тесты LLM и тесты на размеченных деталях пропускаются
PRINTPLAN_NO_SCIPY=1 pytest -q             # те же тесты без scipy (чистый numpy)
STE_SLICER_SRC=ПАПКА pytest -q tests/test_slicer_api_surface.py   # сверка адаптера с исходниками STE Slicer и Uranium
python tools/dev_server.py                 # чат плагина на тестовом слайсере в памяти: http://127.0.0.1:17531/

cd plugin/AIAssistant
python -m printplan plan модель.stl "Кронштейн под нагрузку, PETG, без поддержек" --trace
python -m printplan plan модель.stl задание.docx --json plan.json
python -m printplan parse задание.docx     # только этап 1
python -m printplan kg-report              # граф материалов для ручной проверки
```

Подключение к LLM настраивается только через окружение (ключ в исходники не попадает):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `STE_LLM_API_KEY` | — | ключ OpenAI-совместимого API; без него план строится по правилам |
| `STE_LLM_BASE_URL` | `https://api.timeweb.ai/v1` | адрес API |
| `STE_LLM_MODEL` | `dashscope/qwen3.8-flash` | модель |
| `STE_LLM_STREAM` | `1` | потоковый ответ: нет обрывов по таймауту, есть прогресс для интерфейса |
| `STE_LLM_STAGE1_EXTRA`, `STE_LLM_STAGE6_EXTRA`, `STE_LLM_AGENT_EXTRA` | для Qwen: `{"enable_thinking": false}`, `{"thinking_budget": 1024}`, `{"enable_thinking": false}` | параметры запроса по этапам и для агента чата (JSON); `{}` отключает |
| `PRINTPLAN_NO_SCIPY` | — | принудительно без scipy |

В плагине адрес, модель и ключ задаются в окне настроек чата; `STE_LLM_API_KEY` используется, если ключ там не задан.

## Инструменты

**Прогон по набору деталей:**

```bash
python tools/run_cases.py --dir ПАПКА_С_ДЕТАЛЯМИ [--no-llm] [--images] [--only ПОДСТРОКА]
```

- В папке — по подпапке на деталь: STL, задание (.docx/.txt/.md) и, по желанию, фото.
- Окончание имени подпапки «- 3D» или «- 5D» задаёт ожидаемый режим.
- Скрипт печатает таблицу «ожидание — результат», а полные результаты пишет в `out/cases/`.
- С переменной `PRINTPLAN_EXAMPLES_DIR` та же папка используется в `tests/test_examples.py` и в живых тестах.

**Пересборка каталога слайсера:**

```bash
python tools/build_slicer_catalog.py --repo ПУТЬ_К_ИСХОДНИКАМ_STE_SLICER   # по умолчанию third_party/STE-Slicer
```

Скрипт строит `data/slicer_catalog.json` — снимок конфигурации Hybrid 530 V5.2.4 из исходников STE Slicer. Нужны исходники с определениями этого принтера: в публичном репозитории https://github.com/stereotech/STE-Slicer есть только V5.2. В каталоге:
- 678 настроек с типами, значениями по умолчанию и пределами; пределы области печати вычисляются отдельно для 3D и 5D (высота 300 и 231.1 мм);
- 7 профилей качества;
- 34 материала диаметром 1.75 мм.

## Как вызвать из плагина

Так пайплайн вызывает инструмент `plan_print` (`agent/tools.py`):

```python
from .printplan import pipeline
from .printplan.llm_client import LLMClient

result = pipeline.run(task_text, triangles=tris_zup,   # (N, 3, 3), мм, ось Z вверх, как в STL
                      llm=LLMClient(base_url=..., api_key=..., model=...),
                      ctx=MySlicerContext(),            # опционально, см. slicer_context.py
                      on_event=send_to_chat)            # события этапов для окна чата
plan, actions = result["plan"], result["actions"]
```

- **Где запускать.** `run()` работает долго (сеть), поэтому его вызывают в рабочем потоке. Обращения к слайсеру выполняются в главном потоке Qt через `app.callLater(...)` (`agent/bridge.py`).
- **Сетки из сцены.** У узла сцены ось Y направлена вверх. Перед вызовом вершины переводят в систему STL: (x, y, z)ₛₜₗ = (x, −z, y)ₛцены (`agent/slicer_live.py`).
- **Контекст слайсера.** `CatalogSlicerContext` проверяет значения по статическому каталогу. Плагин передаёт `LiveCatalogContext`: тот же каталог, но с профилями и материалами, которые слайсер действительно предлагает. `validationState` слайсера читается после записи настроек в `set_settings`.

Состав `result`:

| Поле | Что внутри |
|---|---|
| `plan` | план: вердикт, режим, профиль, материал, ориентация, настройки, риски, подсказки, отступления, объяснение, вопросы |
| `source` | `llm` или `fallback` |
| `settings` | итоговые настройки: Θ0 плюс поправки плана; у каждой настройки есть причина и источник |
| `orientation` | матрицы поворота в системах STL и сцены |
| `actions` | шаги для MCP-слоя |
| `evidence` | разбор текста, геометрический пакет, пакет материалов |
| `attempts` | попытки LLM с ошибками проверки |
| `trace` | события этапов |

## Как это работает

```
текст ─► 1. разбор текста ──────────────────────────┐
модель ─► 2. анализ сетки ─► 2б. ось вращения ─┐     │
                           └► 3. ориентации 3D ─┴─► 4. правила ─┐
                                    5. граф материалов ◄────────┤
                                               6. LLM ◄─────────┘
                                               7. проверка ─► план ─► действия
```

Этапы 1 и 2 идут параллельно. Каждый этап отправляет событие в трассировку.

- **Этап 1. Разбор текста** (`text_parse.py`). Извлекает:
   - явные ограничения: материал, поддержки, режим, качество, высота слоя;
   - 28 флагов задачи с силой 0…1 и источником;
   - числовые требования: температуры, теплостойкость, плотность, модуль, прочность, удлинение, водопоглощение, допуск;
   - назначение детали.

   Работают два извлекателя: принудительный вызов LLM и словарь основ слов с регулярными выражениями. Ответ LLM основной. Флаги, найденные только словарём, добавляются с силой 0.5. Противоречивые флаги (гибкость и жёсткость) сводятся к одному.
- **Этап 2. Анализ сетки** (`mesh.py`): сборка вершин, площадь, объём, центр масс, главные оси, граничные и немногообразные рёбра, согласованность нормалей, вырожденные грани, оболочки, проверка единиц.
- **Этап 2б. Ось вращения** (`symmetry.py`):
   - **положение оси:** точка, к которой сходятся нормали боковых граней (надёжный метод наименьших квадратов);
   - **симметрия:** тело вращения и циклическая симметрия порядка N; индекс считается по сдвигу выборки поверхности при повороте, за вычетом шума выборки;
   - **сквозное отверстие и его диаметр;**
   - **доля «призматической» поверхности.**
- **Этап 3. Ориентации 3D** (`orientation.py`):
   - **кандидаты:** шесть ориентаций «ось вверх» и до трёх «крупная грань вниз»;
   - **показатели:** R_support, R_base, R_slender, R_height и их взвешенная сумма S_o;
   - **запрет поддержек:** оставляет только ориентации без нависаний;
   - **радиальная оценка поддержек для 5D:** при цилиндрических слоях поддержка нужна граням, обращённым к оси.
- **Этап 4. Правила** (`rules.py`):
   - **Выбор 3D/5D** — взвешенная сумма доводов с порогом 2.0 (`MODE_WEIGHTS`). Доводы: тело вращения, циклическая симметрия, поддержки в 3D и 5D, кручение, требования к поверхности, мягкий материал, кольцо без сердцевины, плоская деталь без поддержек.
     - Флаги, которые вывела только LLM, учитываются с половинным весом.
     - Мягкий материал и кольцо — жёсткие противопоказания: 5D модели не предлагается.
     - **Spiral или Full:** при сквозном отверстии от 4 мм выбирается Spiral, а диаметры основания приравниваются к диаметру отверстия. Без отверстия — Full.
   - **Для каждого допустимого режима** правила также дают ориентацию, профиль качества, базовые настройки Θ0 (у каждой — причина), риски и подсказки по конструкции.
- **Этап 5. Граф материалов** (`knowledge_graph.py`, `data/kg.json`). 22 материала Stereotech, свойства, назначения, числовые атрибуты.
   - **Жёсткие фильтры:** плотность из профиля слайсера, мягкий или жёсткий материал, проводящий наполнитель, сильный перегрев. Фильтры по флагам срабатывают, только если флаг подтверждён текстом.
   - **Штрафы** за остальные промахи требований.
   - **Нормированная оценка** с цепочками обоснований.
   - **Конфликты**, если материал задал пользователь.
- **Этап 6. LLM** (`reasoning.py`). Получает компактные факты и обязана ответить вызовом `submit_print_plan`:
   - ориентация выбирается по идентификатору строки таблицы;
   - настройки — списком `{key, value, reason}`;
   - отступление от рекомендаций допускается только с записью в `deviations`.
- **Этап 7. Проверка** (`validation.py`):
   - схема ответа;
   - существование режима, профиля, материала и ориентации;
   - типы и пределы настроек;
   - ограничения пользователя;
   - согласованность с фактами.

   При ошибках модель получает их список, повторов не больше двух. Без LLM или после неудачных повторов строится детерминированный план (`fallback.py`).

## Структура

| Модуль | Что делает |
|---|---|
| `io_utils.py` | STL (двоичный и ASCII), текст задания из .txt/.md/.docx |
| `text_parse.py`, `data/lexicon.json` | разбор текста: LLM, словарь, числа, слияние |
| `mesh.py`, `geometry.py` | анализ сетки; повороты, лучи, ближайшие соседи, связность |
| `symmetry.py` | ось вращения и её признаки |
| `orientation.py` | ориентации 3D и радиальная оценка для 5D |
| `rules.py` | выбор режима, ориентация, профиль, Θ0, риски, подсказки |
| `knowledge_graph.py`, `data/kg.json` | граф «задача — материал — процесс» и рейтинг материалов |
| `reasoning.py`, `schema.py`, `llm_client.py` | системный промпт, схема плана, клиент OpenAI-совместимого API |
| `validation.py`, `fallback.py` | проверка плана и детерминированный план |
| `slicer_context.py`, `data/slicer_catalog.json` | что есть в слайсере и проверка значений |
| `actions.py` | план → действия; переход STL (Z вверх) → сцена (Y вверх) |
| `pipeline.py`, `__main__.py` | оркестрация и командная строка |

## Известные ограничения и открытые вопросы

- **Граф материалов.** Список материалов, плотность и температуры взяты из профилей STE Slicer. Связи «назначение → материал» основаны на описаниях Stereotech. Числовые атрибуты (теплостойкость, модуль, водопоглощение и т. д.) и большинство весов — оценки по типичным значениям для семейства полимеров, их нужно заменить данными из даташитов и проверить (`python -m printplan kg-report`).
- **5D Spiral при большом отверстии.** Можно ли подобрать стержень-основание по диаметру отверстия, или в этом случае правильнее 5D Spiral Full? Нужно подтвердить у Stereotech.
- **Мягкие эластомеры (линейка Sealant) в 5D** сейчас запрещены. Тоже нужно подтвердить.
- **Пороги и веса** выбора режима, симметрии и ориентации подобраны вручную. Каждую новую деталь с эталонным режимом стоит прогонять через `tools/run_cases.py`.
- **Каталог слайсера** собран из исходников STE Slicer с определениями Hybrid 530 V5.2.4. Его нужно сверить с используемым дистрибутивом.
- **Отступления LLM.** Обоснования модели могут быть непоследовательными по смыслу, а этап проверки такие противоречия не ловит.
- **Посторонние вопросы в чате** не отсекаются: с языковой моделью она может ответить на любую тему, а без неё любой текст при модели на столе считается заданием на печать и запускает `plan_print`.
- **Долгая 5D-нарезка.** Нарезка крупных деталей в 5D может занимать минуты; плагин ждёт одну нарезку не дольше 15 минут.
